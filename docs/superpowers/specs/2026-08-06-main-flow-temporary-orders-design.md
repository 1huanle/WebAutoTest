# 主流程临时医嘱新增与逐条执行设计

## 目标

在主流程完成开始透析后，按截图新增两条临时医嘱，然后获取临时医嘱列表中当时所有未执行记录，对每一条分别打开“执行医嘱”弹窗并点击“执行”。

## 新增医嘱数据

第一条医嘱：

- 医嘱名称：陈奕源测试；自动补全候选：陈奕源测试mg*。
- 医嘱描述应为：mg* 分散片。
- 单次用量：10；单位由页面联动为 mg。
- 开药数量：1；单位由页面联动为支。
- 给药途径：皮下注射。
- 执行频率：上午。
- 执行科室、诊断和备注保持空白。

第二条医嘱：

- 医嘱名称：陈奕源低分子肝素测试；自动补全候选：陈奕源低分子肝素测试12μg*1。
- 医嘱描述应为：12μg*1 注射剂。
- 单次用量：12；单位由页面联动为 μg。
- 开药数量：1。
- 给药途径和执行频率按用户确认保持空白。
- 执行科室、诊断和备注保持空白。

医嘱时间、开始时间和提醒日期使用页面打开弹窗时自动生成的当前值，不写死截图时间。

## POM 边界

`TemporaryOrderDialog` 负责新增医嘱弹窗。医嘱名称、给药途径和执行频率是真实页面的自动补全输入框，POM 输入查询值并点击指定候选；执行科室和诊断继续使用下拉控件；普通数值和备注直接填写。

新增 `TemporaryOrderExecutionDialog`，备注属于“血液透析 > 临时医嘱 > 执行医嘱”。它使用真实字段名读取执行时间、执行人员、核对人员和备注，校验执行人员与核对人员均为“陈奕源”，备注保持空白，然后点击精确角色为按钮、名称为“执行”的控件并等待弹窗及遮罩关闭。

`TemporaryOrdersSection` 提供两个高层方法：

- `add_orders(orders)`：依次打开新增弹窗、填写、校验联动描述并确认。
- `execute_all_unexecuted(execution)`：先快照当前所有 `.tx_yz_checkbox[data-zxsj=""]` 的 `data-yzid`，然后按 ID 逐条勾选、打开执行弹窗、执行并校验该记录不再处于未执行状态。

已执行记录不重复执行。执行期间新出现但不在初始快照中的记录不纳入本轮，保证本次运行的集合稳定。

## 主流程顺序

主流程顺序扩展为：选择患者、透前评估、透析处方、开始透析、新增两条临时医嘱、执行当时全部未执行医嘱。任一前置步骤失败时，不进入后续临时医嘱写入。

## 测试策略

- YAML 测试校验两条医嘱和执行人员数据，确认第二条未配置给药途径与执行频率。
- 本地新增弹窗测试使用真实字段类型，覆盖三个自动补全输入框、联动描述、确认与遮罩关闭。
- 本地临时医嘱列表测试包含数量不固定的未执行记录和一条已执行记录，验证每个未执行 ID 恰好执行一次，已执行记录不处理。
- 主流程记录测试验证临时医嘱发生在开始透析关闭之后。
- 完整测试套件不收集 `tests/main_write.py`，不保存真实患者数据。

## 范围边界

- 不核对医嘱，不删除医嘱。
- 不执行已经存在执行时间的医嘱。
- 不在自动验证中新增或执行真实患者医嘱。
