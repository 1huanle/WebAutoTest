# 主流程总超滤量期望值修复设计

## 背景

主流程填写透前评估时，测试数据将“预计脱水量”填写为 `0`，页面联动计算出的“总超滤量”也是 `0`。当前 `data/main_write.yaml` 仍将“总超滤量”期望值配置为 `1`，导致流程在点击透前评估确认按钮之前失败。

## 修复范围

- 将 `data/main_write.yaml` 中 `pre_dialysis_assessment.expected.total_ultrafiltration` 从字符串 `"1"` 调整为字符串 `"0"`。
- 同步更新 `tests/test_main_write_flow.py` 中对截图数据的完整字典断言。
- 保留“总超滤量”校验，不删除或弱化透前评估联动值检查。
- 不修改透前评估 POM、主流程编排逻辑、透析处方数据或其他业务模块。

## 测试方式

1. 先将测试期望调整为 `"0"`，保持 YAML 为 `"1"`，运行目标测试并确认因值不一致而失败。
2. 再将 YAML 调整为 `"0"`，运行目标测试并确认通过。
3. 运行 `tests/test_main_write_flow.py`、透前评估 POM 测试和完整测试套件，确认没有回归。

真实写入文件 `tests/main_write.py` 不在自动验证中执行，避免在修复阶段保存患者数据。
