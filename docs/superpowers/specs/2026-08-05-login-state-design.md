# 登录状态保存与复用设计

## 目标

允许用户在本机手动完成一次登录后保存 Playwright 存储状态，并让后续测试自动复用该登录会话。

## 组件

- 新增 `utils/auth_state.py`，集中定义 `auth/storage_state.json` 路径并提供状态文件存在性判断。
- 新增 `save_login_state.py`，启动可视化浏览器打开登录页；用户手动登录、选择角色并到达透析管理页后，在终端按回车保存存储状态。
- `conftest.py` 创建浏览器上下文时检测状态文件：存在则传入 `storage_state`，不存在则维持当前无状态行为。
- `.gitignore` 忽略 `auth/storage_state.json`，防止会话 Cookie 和 localStorage 被提交。

## 数据流

用户手动认证后，Playwright 将 Cookie 与 localStorage 写入本机状态文件。pytest 后续创建每个浏览器上下文时加载该文件，页面访问会携带已登录会话；会话过期时，用户删除状态文件后重新运行保存脚本。

## 安全与错误处理

- 状态文件只保留在本机，不能提交、复制或分享。
- 保存脚本不读取账号密码，也不访问 `data/login_data.yaml`。
- 用户按回车前不保存状态；保存前验证当前地址包含透析管理页路径，否则提示先完成登录并返回非零状态。
- 状态文件不存在时，测试继续以当前方式执行，不因缺失状态失败。

## 验证

- 单元测试覆盖状态文件存在与缺失时的上下文选项。
- 保存脚本在未跳转到管理页时拒绝写入状态文件。
- 保存真实状态后，测试运行能够加载该状态文件。
